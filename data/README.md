# داده‌ها (Data)

اینجا داده‌های روزانه‌ی حسن به‌صورت ساختارمند (JSON) ذخیره می‌شود. ساختار **به‌مرور** پخته می‌شود؛ این نسخه‌ی اولیه است.

## ساختار پوشه‌ها

```
data/
├── README.md            ← همین فایل
├── issues.json          ← دفتر مسائل سیستمی + راه‌حل پیشنهادی (زنده)
├── entities/
│   └── people.json      ← دفتر افراد و نقش‌ها
└── daily/
    └── YYYY-MM-DD.json   ← لاگ هر روز (یک فایل برای هر روز)
```

## قالب فایل روزانه (فعلی)

هر فایل روزانه شامل:

| فیلد | توضیح |
|------|-------|
| `date` / `date_jalali` / `weekday` | تاریخ میلادی، شمسی، روز هفته |
| `captured_at` | لحظه‌ی ثبت |
| `summary` | خلاصه‌ی یک‌خطی روز |
| `items[]` | کارها/مسائل/پروژه‌ها/تعاملات/یادداشت‌های روز |
| `automation_opportunities[]` | فرصت‌های خودکارسازی شناسایی‌شده |
| `follow_ups_next[]` | کارهایی که باید پیگیری شوند (با ددلاین) |
| `questions_for_hasan_eod[]` | سوال‌های آخر روز برای حسن |

### هر آیتم (`items[]`)

| فیلد | مقدار |
|------|-------|
| `id` | یکتا: `YYYY-MM-DD-NNN` (ضد تکرار) |
| `category` | مثلاً `تاسیسات`، `فروش`، `حسابداری-چک`، `استخدام-حسابداری`، `R&D-لیزر-زنان`، `R&D-FPV`، `تأمین-واردات` |
| `title` | عنوان کوتاه |
| `type` | `task` \| `issue` \| `project` \| `interaction` \| `note` |
| `status` | `open` \| `in_progress` \| `waiting` \| `scheduled` \| `blocked` \| `done` |
| `priority` | `high` \| `medium` \| `low` |
| `details` | شرح |
| `people[]` | افراد مرتبط |
| `due` / `due_label` | ددلاین (در صورت وجود) |
| `follow_up` | قدم بعدی |
| `automation_idea` | ایده‌ی خودکارسازی |
| `needs_confirmation` | نکات مبهم که نیاز به تأیید حسن دارند |
| `related[]` | ارجاع به idهای مرتبط |

> دسته‌ها و وضعیت‌ها سفت‌وسخت نیستند؛ با جلو رفتن، استاندارد می‌شوند و در نهایت به قالب feed استانداردِ ارکستریتور (بخش ۵٫۵ سند طراحی) نگاشت می‌شوند.

## گردش‌کار روزانه (هدف)

1. **در طول روز:** حسن اتفاقات را می‌گوید → اینجا به‌صورت آیتم ثبت می‌شود.
2. **صبح:** از روی آیتم‌های باز + ددلاین‌ها، پیشنهاد برنامه‌ی روز.
3. **آخر روز:** پرسیدن «کدام کارها انجام شد؟» و به‌روزرسانی `status`ها.
